# 기여 워크플로우(Contribution)

디자인 시스템에 무언가를 추가·변경할 때의 절차다. 이 창고의 실제 관례를 옮긴 것이다.

---

## A. 토큰을 추가할 때

1. **계층을 정한다**(`tokens.md` §3계층): 공용이면 Tier 1, 특정 판 정서면 Tier 2, 구현 노브면 Tier 3.
2. **이름은 역할로** 짓는다(`--danger`, `--accent-ink`). hex값이 들어간 이름(`--lime17`) 금지.
3. **Tier 1 추가 시 `.ohf{}` 토큰 블록 두 곳 모두**에 같은 정의로 넣는다.
   이 stylesheet은 스코프 선언을 **두 사본**으로 지니고 있고(라인 7과 5435), 두 `.ohf{}` 블록은
   **바이트 단위로 동일**하다. 한쪽만 고치면 사본이 갈라진다. **동시 수정이 규칙이다.**
4. 반투명 변형이 필요하면 **새 토큰을 추가**한다(8-숫자 hex 알파). 인라인 `rgba()`를 만들지 말 것.
5. 값 변경은 **정의 한 곳(양쪽 사본)**에서만. 참조자는 `var()`이므로 자동 반영된다.

## B. 컴포넌트를 추가할 때

1. **`.ohf` 자손**으로 마운트되는지 확인(`.ohf` 밖이면 토큰 미적용).
2. 클래스를 `.ohf-<역할>`로 짓고, **색/여백/그림자는 `var()`로만** 토큰 참조(하드코딩 금지).
3. 변형이 있으면 **BEM 수정자 또는 `data-*`로만**(`variants.md`). 상태 `style` 재도색 금지.
4. 미배선 장치는 **`data-off`(+`aria-disabled`)로 정직하게** 표시(honest inert 관례).
5. 스토리를 추가한다(§D). 스토리가 없으면 변형이 시각적으로 검증되지 않는다.
6. `npx tsc --noEmit`로 타입 무오류를 확인한다(이 창고의 상시 게이트).

## C. 검증 관례(이 창고의 QA 문화)

이 창고는 시각 착지를 **"라이브 CDP 동시 실측"**으로 검증한다 — 즉 HF 원본과 OH를 나란히
실제 브라우저(Chrome DevTools Protocol, 예: HF `:9222` ↔ OH `:3100/:9333`)에서 켜고,
**동일 뷰포트(예: 1440×900 Emulation)** 에서 rect·속성·텍스트를 항목별로 PASS/FAIL로 비교한다.
각 커밋 메시지가 이 결과를 남긴다("PASS 71/FAIL 0", "동 rect·동 스타일" 등).
- **시각 회귀를 걸었는지 확인하려면** 이 parity harness와 루트의 `qa-*.mts` 스크립트를 참고.
- 타입 게이트: `npx tsc --noEmit`(exit 0).
- 이유를 **코멘트로 남기는 것**이 이 창고의 원칙이다. CSS 셀렉터 위에 "왜 이렇게 했는지"를
  한국어/영어 주석으로 남긴다(신규 개발자가 주석에서 이유를 읽는다).

> 시각 회귀 자동화 도구에 대한 최종 권고(부모 조사)는 **Storybook + Chromatic**이다.
> 로컬 우선순위(test-runner + axe + Playwright)도 유효하다. 이 문서는 그 권고를 *문서화*하되,
> 현재 라이브 검증은 위 CDP 병행 실측으로 이루어진다.

## D. Storybook 워크플로우

- 실행: `pnpm storybook` / 정적 빌드: `pnpm build-storybook`.
- 설정: `.storybook/main.ts`(stories 글롭), `.storybook/preview.ts`(**`openhiggsfield.css`를 전역 import** →
  스토리가 실제 스코프 스타일로 렌더).
- 새 컴포넌트마다 `*.stories.tsx`를 옆에 둔다. 스토리 파일에서 모듈 import는 **상대경로**로 한다
  (창고에 `@/*` alias가 있으나 Storybook react-vite는 vite 설정이 별개라, 상대경로가 안전하다).
- 변형은 스토리로: 각 변형(BEM/`data-*`)을 `args` 또는 별도 exported story로 시각화한다.
- 자동 문서는 `meta`의 `tags: ["autodocs"]`로 페이지에 렌더된다.

## E. 리뷰·핸드오프

- 이 창고는 **kanban 리뷰 레인**으로 돌아간다: 구현 → `kanban_request_review`(또는 산출물 기반 승인) →
  리뷰 라운드에서 잔여 착지("리뷰 라운드2 잔여 착지" 커밋 다수).
- 같은 파일이 형제 카드와 자주 충돌하면(`AGENTS.md`/hotspot) 조용히 더 얹지 말고
  카드에 `hotspot: <path> — <이유>` 플래그를 남긴다.

## F. 복제(무손실) 규칙 요약

이 stylesheet은 스코프 선언을 두 사본으로 담는다. 실무 규칙은:
- **토큰 정의는 두 `.ohf{}` 블록에 동일하게** 넣기(동시 수정).
- **모양은 캐스케이드의 마지막 선언이 이긴다** — 두 사본에서 같은 클래스를 고칠 때 양쪽을 동기화.
- 두 사본을 *하나의 논리 시트*로 대우하되, "왜 두 사본인가"는 상위 계획(t_c7ffd218)의
  복제 무손실 논거를 따른다. 새 기여자는 이 사실을 알고 한쪽만 고치는 실수를 피할 것.
